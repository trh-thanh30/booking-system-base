# F0 - Core Infrastructure & SaaS Foundation

F0 thiết lập nền tảng SaaS multi-tenant tối thiểu: tenant database, tenant resolution, tenant context, business registry, health readiness/liveness và shared contract giữa API/FE.

Trong kiến trúc hiện tại:

- `Tenant` là account/organization boundary: billing, users, domains, settings.
- `Business` là đơn vị vận hành booking bên trong tenant: branch, brand, location hoặc store.
- Một tenant có thể có nhiều businesses.

## Endpoint đã triển khai

| Method | Endpoint                              | Mục đích                                     |
| ------ | ------------------------------------- | -------------------------------------------- |
| GET    | `/health/liveness`                    | Kiểm tra process API còn sống                |
| GET    | `/health/readiness`                   | Kiểm tra API sẵn sàng nhận traffic           |
| GET    | `/health/live`                        | Alias tương thích cũ cho liveness            |
| GET    | `/health`                             | Detailed health/readiness tương thích cũ     |
| GET    | `/tenants/resolve?host={host}`        | Resolve host/domain thành tenant             |
| POST   | `/tenants/signup`                     | Public business signup, tạo tenant và owner  |
| GET    | `/internal/tenants/:tenantId/context` | Lấy tenant context đầy đủ cho internal/admin |
| GET    | `/platform/tenants`                   | Super Admin xem danh sách tenant             |
| POST   | `/platform/tenants`                   | Super Admin tạo tenant thủ công              |
| GET    | `/platform/tenants/:tenantId`         | Super Admin xem chi tiết tenant              |
| GET    | `/businesses`                         | Business Admin xem businesses trong tenant   |
| POST   | `/businesses`                         | Business Admin tạo business/branch mới       |

## Tenant resolution

Thứ tự resolve tenant trong middleware:

1. Header `x-tenant-id`
2. Header `x-tenant-host`
3. Header `host`

Nếu resolve được, API gắn tenant context vào request:

```ts
req.tenant = {
  id,
  slug,
  name,
  status,
  timezone,
  locale,
  settings,
  domains,
};
```

Route nào cần tenant có thể dùng `@RequireTenant()` và lấy context bằng `@Tenant()`.

## Business signup

Public web app có route:

```txt
/{locale}/signup-business
```

Route này gọi:

```txt
POST /api/v1/tenants/signup
```

Payload tạo tenant và owner account:

```ts
type SignupTenantInput = {
  slug: string;
  name: string;
  default_business_name?: string;
  default_business_slug?: string;
  primary_domain?: string;
  timezone?: string;
  locale?: string;
  settings?: Record<string, unknown>;
  owner: {
    username: string;
    email: string;
    password: string;
    confirmPassword: string;
    full_name?: string;
    phone?: string;
  };
};
```

BE behavior:

- Check `tenant.slug` và `tenant_domain.host` chưa tồn tại.
- Check owner email/username/phone chưa tồn tại.
- Hash password.
- Tạo tenant, tenant settings, optional primary domain.
- Tạo default business trong tenant.
- Tạo owner role `OWNER`, `ACTIVE`, `is_verified = true`.
- Gán owner vào default business bằng `BusinessMembership`.
- Owner đăng nhập qua Business Admin bằng `/auth/login-admin`.

## Platform tenant registry

Platform Admin app dùng `x-auth-context: platform` và role `SUPER_ADMIN`.

```txt
GET  /api/v1/platform/tenants
POST /api/v1/platform/tenants
GET  /api/v1/platform/tenants/:tenantId
```

`GET /platform/tenants` trả `TenantListItem[]` gồm tenant context, domains, settings, `businesses_count` và `users_count`.

## Business registry

Business Admin app có route:

```txt
/{locale}/businesses
```

Route này dùng:

```txt
GET  /api/v1/businesses
POST /api/v1/businesses
```

`/auth/me` trả thêm `businesses`:

- `OWNER`: thấy toàn bộ businesses trong tenant.
- `STAFF`: thấy businesses được gán qua `BusinessMembership`.
- `SUPER_ADMIN` và `CUSTOMER`: mặc định `businesses: []`.

## Database F0

Các bảng nền tảng:

- `tenant`
- `business`
- `business_membership`
- `tenant_domain`
- `tenant_settings`
- `job_run`
- `system_event`

Các bảng hiện có được thêm liên kết tenant optional để không phá dữ liệu cũ:

- `user.tenant_id`
- `asset.tenant_id`
- `notification.tenant_id`
- `activity_log.tenant_id`
